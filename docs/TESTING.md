# Проверки и статус этой поставки

Проверки актуализированы **12 сентября 2026**. Ниже разделены реальные локальные
результаты и проверки, выполняемые только на платформенных runner'ах GitHub Actions.

## Выполнено

| Проверка | Результат |
|---|---|
| `pnpm run check` | 8/8 Node-тестов и production-сборка Vite пройдены, Node.js 22.18.0 |
| `cargo test -p jxl-core --locked` | 12 пройдено, 2 codec-теста ожидаемо ignored |
| `cargo clippy -p jxl-core --all-targets --locked -- -D warnings` | Пройдена |
| `pnpm run tauri -- build --no-bundle` | Windows release executable успешно собран |

Вывод Node-тестов: [node-tests.txt](node-tests.txt).

Синтаксическое преобразование TypeScript не проверяет совместимость реальных
версий React и Tauri. Локальный компилятор TS 5.8.3 также отличается от версии
5.9.x, указанной в package.json; полная проверка должна выполняться после установки
зависимостей проекта.

## Не выполнено здесь

**Сборка libjxl, интеграционные codec-тесты, создание установщиков и их запуск
локально не выполнены.** Они требуют платформенных toolchain'ов и выполняются
матрицей GitHub Actions на Windows, macOS и Linux.

Утилиты `cjxl` и `djxl` не включены в исходную поставку. Нужно выполнить
`pnpm run codecs:build` либо предоставить совместимые бинарники самостоятельно.
Обновлённые проверки GitHub Actions подготовлены, но сами задания в этом сеансе
не запускались. `Cargo.lock` и `pnpm-lock.yaml` зафиксированы.

## Подготовлено для запуска

В Rust-ядре объявлено 19 тестов, из них два интеграционных помечены `ignore`
и включаются отдельно. Некоторые проверки процессов/ссылок выполняются только
на Unix. Наличие тестов не означает, что они прошли компиляцию или выполнение.

Покрываемые случаи:

- ограничение бюджета рабочих потоков;
- отмена и снятие паузы;
- обход вложенных папок, регистров расширений и повторных источников;
- группировка отдельных файлов одного родителя;
- пропуск символических ссылок;
- блокировка выхода пути за корень;
- отсутствие перезаписи существующего файла;
- сравнение каждого байта и длины;
- изменение источника после сканирования;
- ограниченный хвост диагностических сообщений;
- остановка процесса при отмене и тайм-ауте на Unix;
- отказ от публикации, когда кодек успешно завершился, но реконструкция неверна;
- два настоящих JPEG: обычный и прогрессивный, с EXIF и кириллицей в имени;
- повторный запуск без перезаписи;
- повреждённый JPEG и вложенная папка назначения.

Команды:

```bash
pnpm install --frozen-lockfile
pnpm run check
cargo test -p jxl-core --locked
cargo clippy -p jxl-core --all-targets --locked -- -D warnings
pnpm run codecs:build
pnpm run test:integration
pnpm run tauri -- build --no-bundle
```

`pnpm run test:integration` требует реальные кодеки и не пропускает тесты молча.
Для установщиков используйте ручной workflow `release.yml` либо
`pnpm run desktop:build`.

## Ручная приёмка перед своим архивом

| Сценарий | Ожидаемый результат |
|---|---|
| JPEG с EXIF, ICC, поворотом, кириллицей и пробелами | Восстановление в точности совпадает; контрольная сумма верна |
| Каталог с несколькими уровнями | Структура сохраняется под именем исходного корня |
| Существующий `.jpg.jxl` | Не изменяется; статус не подразумевает проверку старого файла |
| Повреждённый JPEG | Ошибка файла, исходник цел, конечный путь не создан |
| Изменение источника между сканированием и конвертацией | Отказ от его обработки |
| Отмена на сжатии и на проверке | Кодек остановлен, временные файлы удалены |
| Пауза, затем отмена | Нет зависшего ожидания; новые файлы не стартуют |
| Очень быстрая серия нажатий «Пауза»/«Продолжить» | Нет расхождения статуса интерфейса и очереди |
| Закрытие окна во время работы | Предложено остановить операцию; окно не убивает её молча |
| Недостаток места / нет прав записи | Ошибка без удаления оригинала и без конечного частичного JXL |
| exFAT | Понятная ошибка, без небезопасного обходного способа записи |
| Принудительное завершение/перезагрузка | Исходники целы, допустимы оставшиеся временные каталоги |
| 10 000+ файлов | Очередь остаётся управляемой, таблица постраничная |
| Установщик на чистой системе без своего libjxl | Встроенные кодеки находятся и запускаются |
| Windows/macOS/Linux, целевые архитектуры | Проверяются отдельно, а не по одной Linux-сборке |

После первого успешного полного прохода зафиксируйте оба lock-файла и
опубликуйте результаты CI вместе с соответствующим коммитом исходного кода.
