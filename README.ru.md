# JPEG Archiver

[English](README.md) · **Русский**

JPEG Archiver — настольное приложение для обратимой перепаковки JPEG в JPEG XL. Проект развивается в репозитории JexFold; текущая версия — **0.0.1**.

Приложение использует официальные `cjxl` и `djxl`, работает локально и после каждого сжатия восстанавливает исходный JPEG и сравнивает его побайтно. Оригиналы не удаляются, а существующие результаты не перезаписываются.

## Возможности

- сжатие JPEG → JXL и восстановление JXL → JPEG;
- выбор файлов и папок, drag-and-drop и рекурсивный поиск `.jpg`/`.jpeg`;
- сохранение структуры исходных папок в отдельном каталоге назначения;
- строгая проверка JPEG → JXL → JPEG и вычисление SHA-256 исходного файла;
- пауза, отмена, настройка параллельной нагрузки и очередь с пагинацией;
- возможность не сохранять JXL, если он не меньше исходного JPEG;
- интерфейс на английском и русском, определение языка системы и сохранение выбора;
- локальная обработка без сетевых запросов во время преобразования.

Приложение не меняет качество, размеры или встроенные метаданные JPEG.

## Установка

Готовые пакеты публикуются на странице Releases репозитория:

- Windows 10/11 — установщик NSIS (`.exe`);
- macOS 11+ — образ диска (`.dmg`);
- Debian/Ubuntu — пакет `.deb`; другие Linux-дистрибутивы — `.AppImage`.

Версия 0.0.1 не подписана. Windows SmartScreen и macOS Gatekeeper могут показать предупреждение о неизвестном издателе. Проверяйте загрузку по файлу `SHA256SUMS`, приложенному к каждому релизу.

## Использование

1. Выберите JPEG/JXL-файлы или исходную папку.
2. Выберите отдельную папку назначения. Она не должна быть вложена в исходную папку, а исходная — в неё.
3. Выберите режим преобразования и параметры обработки.
4. Нажмите **«Начать сжатие»** или **«Восстановить JPEG»**.
5. Проверьте результат в приложении.

Пример размещения результата:

```text
Исходник:   /photos/2026/IMG_001.JPG
Назначение: /archive
Результат:  /archive/photos/2026/IMG_001.JPG.jxl
```

Двойное расширение сохраняет исходное имя и не смешивает одинаково названные `.jpg` и `.jpeg`. Статус `existing` означает только, что файл уже существовал и не был перезаписан; его содержимое при повторном запуске не проверяется.

### Язык интерфейса

Интерфейс поддерживает английский и русский. Настройка **«Системный»** использует язык операционной системы/браузера и переключается на английский, если этот язык не поддерживается. Язык, выбранный вручную, сохраняется локально.

Переводы находятся в `src/i18n/locales/` и используют стабильные семантические идентификаторы, поэтому новые языки можно добавлять без изменения ядра конвертации.

## Важные ограничения

- Каталог назначения должен находиться на файловой системе с поддержкой жёстких ссылок, например NTFS, APFS или ext4. FAT/exFAT не поддерживаются; поведение SMB/NFS зависит от реализации.
- Для каждого активного задания временно требуется место под JPEG, JXL и восстановленный JPEG.
- Сохраняется время изменения файла, но не ACL, Finder-теги, расширенные атрибуты и отдельные XMP/AAE-файлы.
- Символические ссылки не обходятся. Максимум очереди — 250 000 файлов.
- До самостоятельного удаления оригиналов проверьте резервную копию и восстановление нескольких характерных файлов.

## Запуск из исходников

Требуются Node.js 22.12+, Rust 1.88, Git, CMake и C/C++ toolchain. Установите [системные зависимости Tauri 2](https://v2.tauri.app/start/prerequisites/), затем выполните:

```bash
npm ci
npm run codecs:build
npm run tauri -- dev
```

`codecs:build` загружает исходный код официального libjxl v0.12.0, проверяет ожидаемый commit, собирает `cjxl` и `djxl` для текущей ОС и архитектуры и кладёт их в `src-tauri/resources/codecs/`. Кодеки одной платформы нельзя включать в пакет другой платформы.

Для Ubuntu 22.04/24.04 нужны дополнительные пакеты:

```bash
sudo apt-get update
sudo apt-get install -y build-essential git cmake pkg-config \
  libwebkit2gtk-4.1-dev libappindicator3-dev librsvg2-dev patchelf
```

На Windows используются MSVC, Visual Studio Build Tools и Windows SDK. На macOS нужны Xcode Command Line Tools; минимальная версия системы в конфигурации — 11.0.

## Проверки и сборка

```bash
npm run check
cargo test -p jxl-core --locked
cargo clippy -p jxl-core --all-targets --locked -- -D warnings
npm run codecs:build
npm run test:integration
npm run desktop:build
```

Установщики создаются в `target/release/bundle/`. Интеграционная проверка запускает настоящие `cjxl` и `djxl` на обычном и progressive JPEG и требует точной реконструкции. Полный чек-лист находится в [docs/TESTING.md](docs/TESTING.md).

## Ручной релиз

Релизы намеренно запускаются вручную:

1. Обновите версии в `package.json`, обоих Cargo-манифестах и `src-tauri/tauri.conf.json`, затем добавьте секцию в `CHANGELOG.md`.
2. Убедитесь, что изменения находятся в ветке `main` и CI проходит.
3. Откройте **Actions → Release → Run workflow**.
4. Укажите версию без префикса `v`, например `0.0.1`.
5. Workflow проверит версии и теги, соберёт пакеты на Windows, macOS и Linux, сформирует `SHA256SUMS`, создаст тег и опубликует GitHub Release.

Публикация остановится при несовпадении версий, запуске не из `main`, существующем теге, пустых release notes или отсутствии установщика. Windows- и macOS-пакеты пока не подписываются.
